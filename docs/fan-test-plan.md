# 风扇短时测试方案

本方案已获用户批准并执行了一次，结果见 `fan-test-result.md`。执行时版本默认使用EnergyDrv，当前版本默认WMI FullSpeed，复核本方案对应的命令时须显式加 `--energy`。新增启停测试需另行确认。

## 已核实的环境

- 机型为 Lenovo 82TF。
- ACPIVPC 当前服务处于 Running，驱动包为 oem130.inf，版本 15.11.30.14。
- 磁盘上的 AcpiVpc.sys 签名有效，SHA-256 为 c02b879e601c1689425bdd71ec6fc2ccf66d75436e973ab4f209d45473e58c95。
- QueryDosDevice 的 EnergyDrv 映射为 `\Device\EnergyDrv`。
- 除尘支持位与运行状态尚待查询。WMI 类架构存在，固件实际能力尚待查询。
- 原厂 18 秒周期的退出路径由客户端停止。本次准备的周期为 5 秒。
- 程序构建通过，电池与风扇的内存模拟合计 166 项断言通过。

## 待批准的具体动作

用户批准后，先从当前工作目录执行下列查询。

```powershell
.\build\LiteLX.Cli.exe fan status --energy --confirm-hardware-query
```

查询打开 `\\.\EnergyDrv`，发送 IOCTL `0x831020c4`，输入小端 DWORD `[14]`，输出4字节状态。驱动逻辑将其归入 getter，但底层会通过 ACPI `VPCW` 提交命令、`VPCR` 接收数据。AML 侧副作用尚未完整分析，本方案将此查询也纳入批准范围。

仅当查询成功、bit0支持为1、bit1运行为0、bit2与bit3均为0，才继续执行一次下列周期。程序会在启动前再次核对这些条件。其他返回值先停止测试并补充分析。

```powershell
.\build\LiteLX.Cli.exe fan run 5 --energy --execute --confirm-hardware
```

1. 持有跨进程互斥锁，核对机型、磁盘驱动哈希和设备映射。
2. 查询原始状态，确认满足上述条件。
3. IOCTL `0x831020c0`，输入12字节小端 DWORD `[6,1,1]`，启动除尘。
4. 查询回读运行位。若启动结果不符，仍进入停止阶段。
5. 等待5秒。Ctrl+C或GUI取消可以提前进入停止阶段。
6. 同一 IOCTL 输入 `[6,1,0]`，请求停止。
7. 再次查询，确认运行位为0。保存命令输出与异常信息。

本次批准范围只包括上述查询和一次5秒除尘周期。电池模式、EFI文件、固件变量与BCD的写入另行确认。

## 停止与异常处理

普通取消和异常会进入停止路径。程序也会在启动写请求抛错时尝试停止，以覆盖请求部分生效的情形。

如果报告停止失败，可在原操作退出后执行下列人工停止命令。它会影响当前除尘状态，需要确认发起方。

```powershell
.\build\LiteLX.Cli.exe fan stop --energy --execute --confirm-hardware
```

保留当前原厂软件入口供人工处理。强制杀进程、内核阻塞、系统故障可能中断用户态清理。尚无证据证明固件会自行超时停止。当前实现没有独立看门狗，DeviceIoControl采用与原厂一致的同步请求，内核请求阻塞时用户态取消需等待其返回。

当前测试后端选用静态参数已经闭环的 EnergyDrv。原厂现版优先 WMI，82TF 的实际原厂选路尚未通过运行时能力查询确认。两条路径的电机策略等价性仍待验证。

## 通过标准

- 支持与原始状态符合启动前置条件。
- 启动回读运行为1。
- 5秒后或提前取消后，停止回读运行为0。
- 记录用户观察到的风扇声音及转速变化。
- 服务、驱动配置与电池设置维持本轮测试前的配置，此项通过只读复核记录。

通过上述标准后，结论仅覆盖本次已核实机型、驱动和 EnergyDrv 路径。卸载后可用性还需在用户另行批准卸载后验证。
